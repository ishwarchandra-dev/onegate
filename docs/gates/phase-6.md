## Key decisions this phase

1. **The spec is compiled, not just published.** The Go route table and the TS client are both generated from `docs/api/openapi.yaml`; drift is a build failure (panic in `Register`) or a CI failure (`make api-check`), not a review comment. No YAML parsing entered the Go dependency tree — the generator emits Go source.
2. **Auth chain with CSRF scoped to the credential mechanism.** Sessions (cookie-borne) require the double-submit token on mutations; the bootstrap admin token (header-borne) is CSRF-immune by construction and exempt. Public routes rate-limit per client IP; authenticated routes per principal.
3. **Stdlib-only password hashing.** Go 1.24 ships `crypto/pbkdf2`; the admin credential uses PBKDF2-HMAC-SHA256 at OWASP's 600k iterations with a parameter-aware envelope — no new module dependencies, honoring the repo's single-dependency policy.
4. **Zero-dependency charts.** The analytics charts are hand-rolled SVG on the design-system categorical palette tokens (8 hues, AA-verified in both modes), each with an accessible collapsed data table — no chart library entered the bundle.
5. **E2E found a real streaming bug.** The first E2E run hung the logs view: reverse proxies (vite preview) buffer an SSE response whose first flush carries no body bytes. The LogHub now emits a `:connected / retry: 3000` greeting frame on connect (and the dropped-event payload key was aligned to the spec's `count`). The live-logs acceptance ("a gap, not a freeze") is now verified end-to-end through a proxy.

## Carried observations (not blockers; for the graph-master)

- **Data-plane composition gap (pre-existing)**: `cmd/onegate` still resolves proxy targets via `fallback.StaticResolver{Targets: nil}` — the Phase 4 routing engine (registry, watcher, health tracker) is now wired into the composition root for the management plane (health view, hot-reload of dashboard edits) but the proxy data plane does not yet route through it. No graph node owns this wiring; it is a prerequisite for Phase 7 (parity replay) and should be a superseding node (e.g. `p7.dynamic-resolver-wiring`) or folded into `p7.parity-checklist`.
- **Sessions are in-memory by design** (restart logs the dashboard out; the admin account is durable). If session persistence across restarts is wanted later, it is an additive change behind the same `Authenticator` interface.
- **`bun run e2e` requires prior builds** (`make build` + `bun run build`); the CI job does this. Documented in AGENTS.md.
